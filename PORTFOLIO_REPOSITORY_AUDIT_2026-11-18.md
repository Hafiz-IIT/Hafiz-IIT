# Portfolio-Wide Repository Audit — 18 November 2026

## Scope and method

- Inventory: 34 repositories accessible under the connected `Hafiz-IIT` account.
- Exclusion: the profile `README.md` was not read for editing, executed, or modified. No repository README was changed in this audit.
- Code/research review: repository purpose and file tree; primary implementation modules; tests; workflows; experiment protocols/results; manuscript claims and references where applicable.
- Execution: branch-specific GitHub Actions checks were triggered for all 33 project repositories with repair PRs. The two manuscript-only repositories also received citation-completeness PRs and LaTeX CI. The profile metadata script was inspected but deliberately not run because it changes remote repository descriptions/topics; it now defaults to dry-run and requires `-Apply`.
- Change control: all 33 project repositories and the profile repository now have one draft PR each (34 repositories / 34 draft PRs total). Nothing was merged to `main`.

## Executive assessment

The portfolio is a mixture of research benchmarks, deterministic prototypes, domain workflow software, manuscript scaffolds and earlier applications. It should not be represented as 34 production systems or 34 completed research contributions.

The strongest evidence line remains Evidence-Gated Autonomy. The Koopman paper is the only control/robotics extension manuscript in this portfolio with a completed synthetic experiment and machine-readable results. The residual-control, Bayesian action-gating and hybrid-control manuscripts remain protocols/scaffolds without trained RL results. The EXIM multimodal cargo manuscript is an architecture proposal, not an implemented scanner or deployed customs integration.

The first repair wave addresses high-impact implementation defects and claim mismatches. Passing CI does not establish production readiness, physical validity, privacy guarantees, or research novelty.

## Cross-repository engineering findings

1. **CI scope varies.** A green workflow may mean import/syntax checks, unit tests, manifest verification, or LaTeX compilation. It does not mean the entire application was deployed or integration-tested.
2. **Dependency reproducibility is inconsistent.** Several Python/Node prototypes lack fully pinned dependency locks, coverage thresholds, static analysis, type checking or vulnerability scanning.
3. **Security boundaries are mostly prototype-level.** Local permission maps, caller-supplied verifier IDs, in-memory consent, lexical sensitivity filters and synthetic source-independence labels are not substitutes for authentication, authorization, cryptographic provenance or production key management.
4. **Research evidence is mostly synthetic.** Do not convert synthetic scenario counts into real-world attack probabilities, model accuracy, operational savings or physical performance.
5. **Names and titles can overstate maturity.** The repair wave aligns descriptions/titles for the Koopman prediction lab, residual-control scaffold, Bayesian action gate and hybrid fixed-residual prototype with what is actually implemented.
6. **Reproducibility needs a second pass.** The next portfolio-wide stage should pin dependencies, add coverage reporting, static analysis and security scanning where appropriate, then add integration tests for systems with persistence, HTTP APIs or external services.

## EGA research-specific caveats

- v5 graph-aware admission is a graph-based admission policy; it is **not** a complete implementation of the DAQC method and does not compute a structural cut metric.
- The prior-art comparison must explicitly position the work against He and Yu's 2026 dependency-aware quorum work, Kahn's independent corroboration work, and the IETF SCITT Attestation Reconciliation Protocol individual Internet-Draft. The IETF draft is not a published standard.
- The registry-root experiment assumes the verifier retains the original pinned public key while the corresponding private key is compromised. A separate trust-store replacement attack is a different threat model and must be labelled separately.
- All v0.4/v5 results remain deterministic synthetic outcomes. No production PKI, live customs data, deployed model, or field attack rate is evaluated.
